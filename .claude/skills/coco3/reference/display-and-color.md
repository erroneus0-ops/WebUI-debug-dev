# CoCo 3 display modes and the 64-color palette

Full color table:
`../../coco/reference/xls-conversion/reference-tabs/coco-3-colors.csv`
(64 rows, RGB and CMP/composite index side by side, with color name).
Register addresses controlling mode/resolution/border:
`gime.md` (`$FF98`-`$FF9A`).

## How the palette works

The CoCo 3 exposes 64 colors, split across two monitor types with
**different numeric indices for the same visual color** — the table
maps between them so you can target either. Sample rows (RGB index, CMP
index, name):

| RGB | CMP | Color |
|---|---|---|
| 00 | 00 | Black |
| 01 | 12 | Low intensity blue |
| 02 | 02 | Low intensity green |
| 07 | 16 | Low intensity white |
| 09 | 44 | Full intensity blue |
| 18 | 18 | Full intensity green |
| 36 | 39 | Full intensity red |
| 45 | 41 | Full intensity magenta |

**Practical rule, stated directly in the original documentation:** decide
the color you want, find it in the table, then use the RGB index if
targeting an RGB monitor or the CMP index if targeting a composite
monitor/TV — the two numbers are *not* interchangeable even though they
name the same visual color, because RGB and composite colors are
generated by genuinely different underlying methods. Using the wrong
column's index against the wrong monitor type produces the wrong color,
not just a slightly-off one.

## Display mode registers

`$FF98` (Video Mode), `$FF99` (Video Resolution), and `$FF9A` (Border)
in `gime.md` are the actual mode-selection registers on the CoCo 3 —
they replace the CoCo 1/2 SAM's `V`/`F` bit fields (see the **coco**
skill's `hardware-io.md`) with a more direct, less bit-packed scheme.
**Not yet independently bit-mapped in this skill** — check
`gime-chip.csv` directly for the full bit layout of these three
registers before writing mode-setting code; don't assume CoCo 1/2 SAM
bit semantics carry over.

## Relationship to the CoCo 1/2 SG12 hack

The **coco** skill documents an undocumented CoCo 1/2 semigraphics mode
(SG12) reached via specific SAM `V`-bit combinations. The CoCo 3's GIME
provides its own richer set of *documented* graphics modes at
comparable or better resolution/color depth — when porting code that
relies on SG12 specifically for its CoCo 1/2 compatibility, check
whether a genuine CoCo-3-native mode via `$FF98`/`$FF99` better serves
the same visual goal, rather than assuming SG12 itself is the only path
forward on CoCo 3 hardware (real hardware compatibility mode aside).
